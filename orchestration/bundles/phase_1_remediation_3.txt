Per orchestrator instruction argus-phase-1-remediation-003

1. **Finding #2** (`63742c3`) — pagination accepted an unverified
   persisted boundary. `ReconciliationEngine._fetch_all_pages()` treated
   an empty/short page as proof a persisted `boundary_signature` had been
   reached, relying on the provider's `until` truncation rather than
   ever observing the boundary itself — a pruned/incomplete provider
   response was indistinguishable from genuine success. Rewritten to
   never pass `until_signature` to the provider (Solana's `until` is
   exclusive, so the boundary itself is unobservable if honored) and
   instead walk purely via `before_signature`, scanning every returned
   item for a direct signature match. Only a direct match confirms
   success; an empty/short page reached without one is now a distinct,
   explicit DEGRADED failure with an operator-visible reason. 6 new
   adversarial unit tests plus a real-Postgres replay test
   (`test_replay_pruned_boundary_never_advances_watermark_or_loses_prior_state`)
   prove a pruned/missing boundary never advances the watermark across
   two independent process restarts.

2. **Finding #3** (`6a1b081`) — Helius result-contract failures could be
   recorded as OK usage. `HeliusRpcClient._rpc()` recorded `ok` after
   only top-level JSON-RPC envelope validation; every method's own
   nested contract validation ran afterward, outside the accounted
   operation, so a malformed method result left an `ok` usage row behind
   before raising. `_rpc()` now takes a `validate` callback invoked
   inside the same accounted `process` closure `send_with_usage()`
   decides the terminal outcome from; every nested validation failure is
   now `contract_error`, distinguished from a well-formed provider-level
   `rpc_error`. Audited DexScreener/GeckoTerminal/Jupiter for the same
   pattern — all three already validated fully inside their accounted
   operations; no fix needed there. Added malformed-nested-result tests
   for every Helius method (`get_transaction`, `get_signatures_for_address`,
   `get_signature_statuses`, `get_balance`, `get_token_accounts`), most of
   which previously had no usage-outcome assertion at all (and
   `get_token_accounts` had no test coverage whatsoever).

3. **Finding #4** (`4510522`) — streaming usage-recorder failures
   disappeared silently. `IngestionManager._record_streaming()` wrapped
   the recorder call in `contextlib.suppress(Exception)` with zero
   signal. Replaced with the same `usage_recorder_failed` structured
   warning pattern round 2's finding #8 established for the HTTP path —
   safe metadata only (provider, wallet address, request class, the
   delta shape attempted, error class/message), no credential material,
   never masking the real stream outcome or control flow. Tests cover
   connection/subscription, reconnect, and byte-accounting recorder
   failures individually, plus an end-to-end run proving a permanently-
   failing recorder never changes the real ledger/watermark outcome of a
   full disconnect/reconnect cycle.

4. **Finding #5** (`1ba5403`) — parse-attempt evidence omitted required
   build/config/git identity. Migration 0004's `parse_attempts` recorded
   `parser_version`/`input_payload_hash` but no build hash, config hash,
   MASTER_SPEC hash, or git commit — an immutable attempt could not be
   reproduced against the exact code/configuration that produced it.
   New migration 0006 adds four NOT NULL columns, each with a
   `length(...) > 0` CHECK constraint; pre-existing round-2 rows are
   backfilled with an explicit `NOT_CAPTURED_PRE_R3_REMEDIATION` sentinel,
   never a fabricated hash. New identity sources: `argus.config.git_commit_sha()`
   (`git rev-parse HEAD`, or an explicit `GIT_COMMIT_UNAVAILABLE`
   sentinel, never fabricated); `argus.parsing.generic_parser.PARSER_BUILD_HASH`
   (a SHA-256 of the parser module's own source, computed at import
   time — distinct from the human-assigned `PARSER_VERSION` label and
   from a git commit that changes on any repo commit, not just parser
   changes); `argus.ingestion.parse_ledger.capture_parse_identity()`
   bundling all four. `ReconciliationEngine` now requires an explicit
   `parse_identity` argument (no default); `argus ingest run`
   (test-mode and live) and `argus ingest reparse` all call
   `capture_parse_identity()` explicitly. A new
   `tests/integration/test_migrations.py` runs every migration scenario
   the instruction names — migration-from-zero, upgrade-from-0003
   through head, upgrade-from-0005 backfilling the sentinel (plus
   proving the CHECK constraint rejects an empty value), downgrade,
   upgrade-head idempotency/restart-safety, and a downgrade-then-upgrade
   round trip — against a disposable scratch Postgres database created
   and dropped per test, never the shared dev database.

5. **Finding #6** (`e0753cc`) — finalization provider failure was
   silently converted to zero promotions. `sweep_finalization()` caught
   every provider exception and returned a bare `0`, making "nothing
   finalized" and "the provider check failed" indistinguishable to every
   caller. Now returns `FinalizationSweepResult(ok, promoted, reason)`:
   `ok=True, promoted=0` covers every legitimate no-op (no
   `RecentEventSource` wired, wallet not yet reconciled, no candidates,
   a genuine zero-result check, or a duplicate re-observation of an
   already-FINALIZED event); `ok=False` covers a provider exception, a
   malformed/mismatched-cardinality response (now explicitly checked
   rather than relying on an uncaught `zip(strict=True)` `ValueError`),
   or a per-event append failure — which no longer aborts the whole
   batch, so `promoted` still counts whatever else genuinely succeeded.
   Cancellation is never caught, matching `send_with_usage()`'s policy.
   `IngestionManager._run_finalization_sweep` now logs a structured
   `finalization_sweep_failed` warning whenever a sweep comes back
   `ok=False`; `sweep_finalization()` still never touches wallet health,
   so there is nothing for a failed sweep to falsely restore.
