B. What was built

Per orchestrator instruction `argus-phase-2-remediation-002`
(`AUTHORIZED_ACTION: REMEDIATE_ONE_REMAINING_FROZEN_PHASE_2_BOUNDARY_
DEFECT_ONLY`), the independent re-audit closed 7 of the 8 round-1
findings (P2-R1, P2-R3, P2-R4, P2-R5, P2-R6, P2-R7, P2-R8) and left

own test module described a "premature short/empty page" scenario in its
header, but its actual tests only proved that an *ordinary* short final
page and an ordinary empty history are treated as complete -- never that
a caller-supplied expected boundary is respected when the walk truncates
before reaching it. Per this instruction's own scope lock ("Do not
revisit the seven closed P2 findings except for regression tests"), only
this one item was touched.

1. **`src/argus/tokens/historical_acquisition.py`**
   (`ALGORITHM_VERSION` bumped `historical_acquisition_v1` ->
   `historical_acquisition_v2`) -- `acquire_historical_transactions`
   gained a new, optional, typed parameter `expected_oldest_slot: int |
   None = None`: an independently known expected historical boundary
   (e.g. a token's own known creation slot), machine-checkable against
   the observed pagination walk. A local `boundary_satisfied` flag starts
   `True` immediately when no boundary is supplied (nothing to satisfy,
   preserving round-1 behavior exactly) and otherwise flips `True` the
   first time an observed signature's own `slot` is at or below
   `expected_oldest_slot`. Both of the two "natural completion" exit
   points (an empty page, and a short/`< page_size` page) now check this
   flag before letting the walk report `COMPLETE`: if the boundary was
   supplied but not yet satisfied at that point, the result is
   `PARTIAL` instead, with a specific `known_gaps` note naming the
   unsatisfied slot, the page kind (`empty`/`short`), the page number,
   and the earliest slot actually observed so far -- and every
   successfully collected signature/transaction up to that point is
   still returned, never discarded. No other exit path (provider
   failure, ordering fault, duplicate/cycle, safety-ceiling exhaustion,
   per-transaction fetch failure) is touched at all -- each was already
   correctly non-`COMPLETE` regardless of any boundary, so none needed
   boundary-awareness added. A caller-supplied `--partial` flag is never
   the proof anywhere in this path: the comparison is the service's own,
   against `expected_oldest_slot`, not a caller assertion.
2. **`src/argus/cli.py`** (`argus discover acquire-and-run-archaeology`)
   -- gained `--expected-oldest-slot <int>` (optional, defaults to unset
   -> `None`), threaded straight through to
   `acquire_historical_transactions(..., expected_oldest_slot=
   expected_oldest_slot)`. The option is real production CLI wiring, not
   a test-only argument: `argus discover acquire-and-run-archaeology
   --help` shows it, and a real invocation with the flag set (against
   this sandbox's real missing-`HELIUS_API_KEY` state) still produces the
   exact section-108 `LOCAL CREDENTIAL REQUIRED` notice before any
   network call, proving the option reaches the real call site without
   affecting the credential-gated fail-closed path (section C).
3. **`tests/unit/test_historical_acquisition.py`** -- 4 new frozen
   remediation-002 acceptance tests (module total 14 -> 18):
   - `test_r002_premature_short_page_before_boundary_is_partial` --
     boundary not reached, a short page arrives; asserts `PARTIAL`, the
     unsatisfied boundary and page kind named in `known_gaps`, every
     fetched transaction preserved, and the exact provider call sequence
     (`usage_log`) the walk actually made.
   - `test_r002_premature_empty_page_before_boundary_is_partial` -- one
     genuine full page, then an empty page before the boundary; same
     fail-closed assertions, prior page's evidence preserved.
   - `test_r002_boundary_satisfied_reports_complete` -- the expected
     slot IS observed before a short final page; asserts `COMPLETE`,
     `known_gaps is None`.
   - `test_r002_no_boundary_supplied_preserves_prior_short_page_complete_
     behavior` -- the *identical* page shape used in the first test
     above, but with `expected_oldest_slot` omitted entirely; asserts
     `COMPLETE` -- direct proof that omitting the parameter is not
     merely "usually fine" but genuinely, exactly the unconditional
     round-1 behavior, not a coincidentally-passing case.
